# Datasets

SmartCrop AI uses **two datasets** plus small reference tables. They are never merged
row-by-row: the recommender uses the crop dataset for suitability and the price dataset (via the
monthly price model) for market prices.

| | Price dataset | Crop recommendation dataset |
|---|---|---|
| File | `dataset/raw/Maharashtra_Crop_Prices_2023_2025_Cleaned.csv` | `dataset/crop_recommendation/maharashtra_crop_recommendation.csv` |
| Origin | Real mandi (APMC) reports | **Synthetic**, generated by `backend/scripts/generate_crop_dataset.py` |
| Used for | Daily price forecasts (Feature 1); monthly selling-month forecasts and profit (Feature 2) | Suitability classifier (Feature 2) |
| Rows | 246,067 | 4,550 original (650 per crop) + 3,850 synthetic dry/cool-season rows in `crop_dataset_extended.csv` (see README 6.2.1) |
| Crops | Brinjal, Cabbage, Cauliflower, Onion, Potato, Tomato, Wheat | the same 7 |

The earlier 22-crop public dataset (`dataset/raw/Crop_recommendation.csv`) had **no overlap**
with the priced crops and no location/timing columns, so it is no longer used (kept for
reference; its old calendar and commodity map are in `dataset/raw/legacy/`).

---|---|---|
| File | `dataset/raw/Maharashtra_Crop_Prices_2023_2025_Cleaned.csv` | `dataset/raw/Crop_recommendation.csv` |
| Used for | Price forecasting (Feature 1), market outlook in Feature 2 | Agronomic suitability classifier (Feature 2) |
| Rows | 246,067 | 2,200 |
| Crops | 7 | 22 |
| Overlap of crops | **none** | **none** |

## 1. Price dataset

### Source
Provided by the project team as `Maharashtra_Crop_Prices_2023_2025_Cleaned.csv`. The column
layout (State, Market, Commodity, Variety, Arrivals, Min/Max/Modal price in ₹/quintal) matches
the Government of India **AGMARKNET** mandi price reports (agmarknet.gov.in / data.gov.in).
**To confirm:** the exact download source, licence and the cleaning applied before it was named
"Cleaned" are not documented in the file; the team should record them here.

### Preprocessing decisions (`backend/app/ml/price_prediction/preprocessing.py`)

| Step | Rows affected | Decision and reason |
|---|---|---|
| Invalid dates / missing key fields / Modal ≤ 0 | 0 | Would be removed (none found). |
| Min_Price ≤ 0 | 1 | Set to missing, row kept — Modal price is valid and Min is not a model input. |
| Same-day duplicates | 3,834 rows → 1,917 | Merged with the **median** price. Arrivals **averaged**, not summed, because in 83% of groups the arrival figure is repeated identically (summing would double count). |
| Outliers | 610 rows (0.25%) | A modal price > 4× or < ¼ of the median of the same series' previous 15 reports is capped to that bound. Rows are kept; the original value is preserved in `Modal_Price_raw`. The rule looks only backwards, so genuine gradual shocks (e.g. the mid-2023 tomato spike: only 17 of 838 rows capped) are retained, while entry errors like Onion ₹75,000/qtl (Junnar, 2023-02-23) are caught. |
| Net | 1,917 rows (0.78%) merged | No data was discarded in bulk. |

### Daily panel and forecastability
Each (market, crop, variety) series is placed on a continuous daily calendar. Prices are
carried forward at most 7 days over non-trading days; longer gaps stay missing (no
interpolation). A per-crop **state-level series** (median across reporting markets) is
added — it covers 1,086–1,090 of 1,096 days for every crop.

| Crop | Market series | Offered for forecasting (≥ 180 reported days) | Median coverage |
|---|---|---|---|
| Brinjal | 56 | 44 | 61% |
| Cabbage | 50 | 40 | 64% |
| Cauliflower | 50 | 39 | 64% |
| Onion | 197 | 98 | 26% |
| Potato | 64 | 33 | 48% |
| Tomato | 69 | 49 | 66% |
| Wheat | 274 | 117 | 20% |

(Series here are market × variety, so counts exceed the number of markets.)

### Limitations
* One state only; 7 crops only. Predictions are offered **only** for these crops and for
  series with enough history.
* Data ends 2025-12-31. Forecasts are made *as of* a date inside the dataset; the system
  does not pretend to know prices after the last available report. New data can be dropped
  into `dataset/raw/` (same columns) and the pipeline re-run.
* Arrivals units are as reported by the source; ~0.3% of values look averaged upstream.
* Three full years give only three observations of each month for seasonal patterns.

## 2. Crop recommendation dataset (synthetic, 7 crops)

### Why it is generated
No public row-level dataset links soil tests + weather + city + planting/selling month to
these 7 crops. The dataset is therefore **simulated from documented agronomic knowledge**
and is labelled synthetic in the API, the UI notes and the model metadata. Regenerate with
`python -m scripts.generate_crop_dataset` (seed 42, deterministic).

### Columns
| Column | Range | Meaning |
|---|---|---|
| N, P, K | 0–140, 5–145, 5–205 | Soil nutrients (kg/ha) |
| ph | 3.5–9.9 | Soil pH |
| temperature | 8.8–43.7 °C | Growing-period average |
| humidity | 14–100 % | Growing-period average |
| rainfall | 20–299 mm | Growing-period monthly average |
| state | Maharashtra | |
| city | 11 cities | Pune, Nashik, Nagpur, Mumbai, Chhatrapati Sambhajinagar, Kolhapur, Solapur, Satara, Jalgaon, Amravati, Ahilyanagar |
| planting_month, selling_month | 1–12 | |
| label | 7 crops | |

### How a row is produced
1. Crop (balanced classes) → city, weighted by the crop's main growing belts (e.g. onion:
   Nashik, Ahilyanagar; potato: Pune, Satara; wheat: Vidarbha, Jalgaon) with a small base
   weight for every city.
2. Planting month from the crop's planting windows; growing time within its crop cycle;
   storable crops (onion, potato, wheat) are sometimes held 1–N months → selling month.
3. Weather = 55 % city climate over the growing months (`city_climate_normals.csv`) + 45 %
   the crop's preferred conditions, plus noise (farmers grow a crop where/when it does well).
4. Soil = crop-specific nutrient-management targets (typical package-of-practice ranges)
   shifted by the city's dominant soil (black cotton soils alkaline and K-rich; Konkan
   laterite and Western-Ghat soils more acidic), truncated to the bounds above.

Summary statistics: `dataset/reports/crop_dataset_summary.json`.

### Limitations
* **Synthetic**: the classifier learns the generator's assumptions, not observed farm
  outcomes. Its accuracy (85 %) measures how separable the simulated crops are; it is not a
  field-validated accuracy. Replace with surveyed farm records when available — the
  training script needs only the same columns.
* Climate normals and crop profiles are rounded, indicative values (see section 3).
* Soil type is not modelled; a soil type entered by a user is stored only.

## 3. Reference tables (`dataset/crop_recommendation/`)

| File | Content | Status |
|---|---|---|
| `crop_season_calendar.csv` | Planting months, growth months (min–max), max storage months, storable flag per crop | General Maharashtra cropping calendar; verify locally |
| `crop_economics.csv` | Yield (q/acre), cultivation cost (₹/acre, 2024), post-harvest loss %, storage loss %/month, storage cost ₹/q/month, marketing cost % | **Approximate assumptions** (`verification_status = approximate_assumption`); replace with local cost-of-cultivation data |
| `city_climate_normals.csv` | Monthly mean temperature, humidity, rainfall per city | Rounded approximations of climatological normals |
| `city_market_map.csv` | Which APMC markets in the price data belong to each city | Built from the market names in the price dataset |

Costs are inflated from their reference year to the planting year with the same annual
inflation assumption as the price model (5 %).

### Monthly city price panel
`backend/scripts/train_monthly_price_model.py` writes
`dataset/processed/price_monthly_city_panel.csv`: per (city, crop, month) the median modal
price and total arrivals over the city's markets, plus a state-wide series per crop. A month
needs ≥ 4 mandi reports; series need ≥ 24 observed months (80 of 84 series qualify).
Where a city has too little data for a crop, the state-wide price is used and the UI says so.

Month → season windows (`backend/app/ml/common/seasons.py`): Kharif Jun–Sep, Rabi Oct–Jan,
Zaid Feb–May.

## 4. Synthetic data — summary

* `dataset/crop_recommendation/maharashtra_crop_recommendation.csv` — synthetic (section 2),
  used to train the suitability classifier.
* `backend/tests/test_ml_pipeline.py` / `test_economics.py` generate small random series to
  unit-test feature code.
* All prices shown to users come from the real mandi data (history) or from the models
  trained on it (projections).
